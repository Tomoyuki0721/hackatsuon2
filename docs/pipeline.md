# データ抽出パイプライン

原典PDFから確定データ(`data/projects/*.json`)までの流れと、各段階のスクリプト。

**この仕組みは全自動ではありません。** スクリプトが作るのは「候補」であり、
人が原典と突き合わせて確認したものだけが確定データになります。
自動的に `data/projects/` へ書き込むスクリプトは、意図的に用意していません。

```
原典PDF
  │  npm run extract        scripts/extract.mjs
  ▼
data/raw/*.txt                                   … RAW(pdftotext の生出力)
  │  npm run parse          scripts/parse-outcomes.mjs
  ▼
data/candidates/*.json                           … 自動抽出 + 正規化(候補、_review 付き)
  │  npm run match          scripts/match-projects.mjs
  ▼
マッチング結果(exact / alias / fuzzy / manual)
  │  ★ 人が確認して取り込む(手作業)
  ▼
data/projects/<projectId>.json                   … 確定データ
  │  npm run validate       scripts/validate.mjs   ← CIでも自動実行
  ▼
検証OK → ビルド・公開
```

## 各段階

### 1. extract — PDF をテキストにする

```bash
npm run extract -- --src . --out data/raw
```

`pdftotext -enc UTF-8` を使います。**`-enc UTF-8` は必須**で、付けないと日本語が壊れます。
`--layout` を付けると表の桁が保たれますが、欄がずれることがあるため既定では付けません
(財源内訳の列対応が崩れた実例があります)。表を読むときだけ併用してください。

原典PDFはリポジトリに含めていません(`.gitignore` で除外)。手元に置いて実行します。

### 2. parse — 成果報告書から事業ごとの候補を作る

```bash
npm run parse -- --in "data/raw/16 令和7年度主要な施策の成果に関する説明書.txt" --year R7 --doc R7成果報告書
```

「主要な施策の成果に関する説明書」は1事業1シートの構成で、次の要素を取り出します。

- 事業名 / 所管課 / 予算科目 / 総計基本施策分類
- 【目的】【事業内容】【成果】【課題】
- 予算の執行状況(予算額・決算額)と決算額の財源内訳

**掲載ページは目次から取ります。** 各シートに書かれた「決算書ページ」は
*決算書*のページ番号であって成果報告書自身のページではないため、
出典として使うと別資料を指してしまいます(実際にこの取り違えが起きました)。

**財源内訳の並び**: テキスト抽出後の数値は
`[予算額, 決算額, 国(県)支出金, 市債, その他, 一般財源]` の順に並びます。
複数年度・複数事業のシートで確認した並びですが、崩れる可能性があるため、
後ろ4つの合計が決算額と一致するかを必ず検算し、合わなければ信頼度を「低」に落として
`_review` に理由を残します。

抽出できなかった項目は `null` のままにします(推測で埋めません)。
「一般行政経費」「職員人件費」などの共通経費は `_excludedAsCommonExpense` を立てて
事業マスターの対象外であることを示します(`matching-rules.md`)。

### 3. match — 既存の事業マスターに突き合わせる

```bash
npm run match -- --candidates data/candidates/R7成果報告書.json
```

`exact` → `alias` → `fuzzy` の順に判定し、決まらないものは `manual` として人に回します。

**事業名が同じでも款が異なれば別事業**です。地域おこし協力隊事業は
2款(企画調査費)・5款(労働諸費)・7款(観光総務費)にそれぞれ存在し、所管課も内容も違います。
このスクリプトは同名・別款を検出したら `manual` にし、「別事業として新規作成」と提示します。

### 4. 人の確認(ここは自動化しない)

候補の `_review` を読み、原典PDFの該当ページと突き合わせ、
必要な項目を `data/projects/<projectId>.json` へ転記します。
このとき出典(資料名・ページ・原文)を必ず添えます。

### 5. validate — 確定データを検証する

```bash
npm run validate
```

CI(`.github/workflows/deploy.yml`)のビルド前にも実行され、失敗するとデプロイされません。

- すべての値が `value` / `citation` / `confidence` の形になっているか
- **値があって信頼度「高」なのに出典が無いものは不合格**
  (出典を出せないものは信頼度を下げるか、値を `null` にする)
- 資料名・事業ステータス・新規事業ラベルが既知の集合に含まれるか
- 財源内訳の合計が決算額と一致するか(ずれる場合は `_note` での説明が必要)
- ファイル名が `projectId` と一致しているか

## 計算値をデータに持たせない方針

執行率・不用額・増減率・単価は `data/projects/` に保存していません。
`src/lib/format.ts` と `src/lib/project-helpers.ts` が表示時に計算し、
画面上で「計算値」と明示します。

原典に無い数字を確定データに混ぜないための切り分けです。
原典に執行率の記載がある場合はその値を保存し、無い場合のみ計算値を表示します。
