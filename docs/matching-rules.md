# 事業名マッチングルール(初稿)

前提: [source-inventory.md](./source-inventory.md) §3、[data-model.md](./data-model.md) §3

## 1. マッチングの入力と出力

- 入力: 各資料(決算書/予算書/予算説明資料/成果報告書)から自動抽出した候補レコード
  (`rawName`, `sourceDocument`, `year`, `budgetCategory(款項目)`, 金額 等)
- 出力: `ProjectMatchLog`(`projectId`, `matchMethod`, `confidence`)を伴う、
  `ProjectMaster.projectId` への割当て

## 2. マッチング手順(優先順位順)

1. **exact(完全一致)**: `rawName` が既存 `ProjectMaster.canonicalName` と完全一致、
   かつ `budgetCategory` の「款」が一致 → `confidence: 高`
2. **alias(別名一致)**: `rawName` が `ProjectMaster.aliases` のいずれかと完全一致
   → `confidence: 高`(ただし新規alias追加時は人が一度確認したもののみ登録する)
3. **fuzzy(あいまい一致)**: 以下のいずれかに該当する場合
   - 括弧書きの補足のみ異なる(例: 「一般行政経費(企画調査費)」と「一般行政経費(職員厚生費)」は
     **別事業として扱う**。括弧内が款/項/目の区別を表しているため、削って同一視してはいけない)
   - 送り仮名・中黒(・)の有無のみ異なる(例: 「移住・定住促進事業」⇔「移住定住促進事業」)
   - 文字列類似度(編集距離ベース)が閾値以上、かつ`budgetCategory`が一致
   → `confidence: 中`。**人間確認前は仮割当てとして扱い、UI上で「要確認」バッジを出す**
4. **manual(手動)**: 上記いずれにも該当しない、またはfuzzyの確信が持てない場合は
   `projectId`を割り当てず、`未マッチ候補`キューに残す → 人が`ProjectMaster.aliases`へ
   追記するか、新規`projectId`を発行する

## 3. 「同名だが別事業」の判定基準

- **款が異なれば原則別事業**とする(例: 「地域おこし協力隊事業」は総務費・労働費・畜産費・
  観光費・教育費に同名で存在するが、所管課も内容も異なるため、款ごとに別`projectId`を発行する。
  `canonicalName`は共通でよいが`projectId`のsuffixで区別する: 例
  `local-vitalization-corps-somu`, `local-vitalization-corps-kanko` 等)
- **款が同一で年度によって項/目コードが変わっている場合**は、事業名一致を優先して同一
  `projectId`とみなし、`budgetCategory`の変遷を`ProjectYearRecord`側に年度ごと記録する
  (組織改編で目のコードが振り直されるケースがあるため)

## 4. 「同名だが包括的経費」の除外基準

「一般行政経費」「職員人件費」「施設の維持管理に関する経費」のような、款/項/目ごとに
繰り返し登場する**包括的経費項目**は、そのままでは事業マッチングの対象にしない
(成果報告書に個別の「目的・成果・課題」が書かれないため、政策サイクルの追跡に適さない)。
これらは`ProjectMaster`化せず、款/目単位の「その他経費」として別集計する扱いとする。
対象は成果報告書の目次に個別事業名として掲載されているものに限定する
(source-inventory.md §2.4で確認済みの通り、目次自体が主要事業のフィルタとして機能する)。

## 5. confidenceの運用

| confidence | 意味 | UI表示 |
|---|---|---|
| 高 | 事業名・款項目とも一致、法定書類間の相互参照(決算書ページ番号等)も一致 | 通常表示。出典アイコンのみ |
| 中 | fuzzy一致、または金額を複数箇所から合算・推定した | 「要確認」バッジ表示 |
| 低 | 自由記述からの数値抽出(【事業内容】欄のサブ事業金額等)で書式が事業ごとに異なる | 「AI抽出・未確認」バッジ表示、数値の隣に必ず原文抜粋を併記 |

低confidenceのデータは**トップページの自動抽出ランキング(予算増減が大きい事業 等)には使わない**
(誤った目立ち方をしてしまうため)。高・中confidenceのみを自動分析の対象とする。

## 6. パイロット5事業での適用結果(§5 source-inventory.md参照)

| 事業名 | 判定 | 備考 |
|---|---|---|
| 移住・定住促進事業 | exact / 高 | 全年度・全資料で表記統一 |
| 結婚支援事業 | exact / 高 | 同上 |
| 地域おこし協力隊事業 | **要・複数projectId分割** | 款ごとに別`projectId`を発行する方針(§3) |
| 子ども医療費助成事業 | exact / 高 | 同上 |
| デジタル水産業戦略拠点事業 | exact / 高(R6から登場、R4は「該当なし」が正) | 存在しない年度を「未マッチ」ではなく「事業自体が未開始」として区別する必要あり → `ProjectYearRecord`は生成せず、`status`欄に開始年度情報を持たせる設計とする
